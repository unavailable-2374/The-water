# 大纲设计与独立审查

本功能依据作者提供的实用评审框架：先明确吸引力、持续发展动力、人物选择及其后果、最终阅读体验，再分别审查通用基础、类型承诺与篇幅/阅读形式。它是辅助作者判断的编辑报告，不是统一行业评分标准，也不保证文学质量。

## 使用

- 新生成的虚构作品总纲，以及全书抽卡选定方向后细化的大纲，保存为待审建议后另行调用规划模型审查。作者在差异审阅中查看报告，再决定是否采纳。
- 已有作品在「规划 → 检查当前大纲」读取当前保存的设定、故事弧、章节计划和已确认相关卡片。此入口只保存报告，不改计划或正文。
- 模型或网络失败显示真实错误，可以重试检查；已经保存的大纲不会为了重试而重新生成。重启后未完成请求显示为中断。
- 关键矛盾或阻碍核心转折判断的关键信息缺失会阻止采纳。修改大纲/作者硬约束/基础计划后须重新检查或生成新建议。审美选择不会阻止作者采纳。
- 旧待审建议保持兼容，可以手动检查；不会伪装成已经审查过的新建议。非虚构文体不套用小说评审。

## 检查内容

报告逐项覆盖十二个维度：读者承诺、情节因果、人物动机与选择、中段积累、节奏及情绪铺垫、世界规则与代价、信息安排、主支线/关系/主题整合、高潮与结局、写作具体性、类型适配、形式适配。类型检查根据作品实际承诺调整，不强制治愈故事冒险、不强制人物变好、不将开放结局或慢节奏视为缺陷。

主要转折按「此前条件 → 行动/事件 → 变化 → 后续影响」追踪；时间表分别记录事件发生、人物获知、读者获知，以及重要物件和证据的形成、获取、保管与转移。重生角色可记得未来，但未来收集的物件/电子数据不能自动存在于重生后的过去，除非作者明确设定允许。

发现分为「已经存在的矛盾」「尚未提供的信息」「审美或定位选择」，附位置、输入原文证据、影响和修改建议。程序校验十二项完整且不重复，并核对证据引用确实出现在输入字符串中；失败报告不能成为采纳依据。具体时间未提供应注明未知，不补造日期。

全书重构的大纲阶段检查新大纲内部与硬约束；保留的旧章节表与正文另列后续影响，不能仅因它们与新方向不同就判定新大纲矛盾。随后章节规划仍需作者另行发起与审阅。

## 持久化与边界

报告保存在现有 `writing_proposals.json.meta.outlineReview`，随数据库备份。输入签名包含大纲、所选方向、作者要求及当前基础计划版本；审查写回和采纳均检查并发变化。只读检查没有采纳入口。生成流程保存建议 ID 作为检查点，重试只继续尚未成功的独立审查。恢复数据库前会中止并等待在途检查。

每份新大纲增加一次独立模型调用，校验修复可能增加调用；所有实际用量包括失败尝试均记录。报告是模型判断，仍可能误判；语句、对白、喜剧效果、恐怖氛围及情感感染力需用关键场面的正文试写验证。
