# 作者中心故事工作台

入口：作品工作室 → **故事工作台**（`/studio/:novelId/workspace`）。桌面端需重新启动以执行 `0011_story_graph.sql`。旧作品直接使用原有场景和情节点；没有来源的时间、关系和证据保持未确定。

## 创作闭环

1. 从原有故事线、场景卡或空白章节开始。在地图中选择场景或事件，查看章节位置、故事时间和因果关系；长篇先显示分卷／故事弧概览，支持搜索、人物筛选、折叠及分页。
2. 修改场景、事件、时间或关系，预览下游影响及关联理由。确定关系和待确认推测分别显示；移除关系时仍展示原关系涉及的影响。作者确认后保存，可按顺序撤销工作台结构修改。
3. 在地图与正文并排视图选择已经保存的原文，关联到场景，或锁定段落。关联记录稳定场景 ID、章节 ID、不可变版本、内容哈希和逐字引句。正文变化后显示失效状态，不自动把旧引句移到别处。
4. 选择场景、整章所有场景或故事弧中的场景，填写“必须发生／允许发挥／不能改动”，创建持久化委托。局部场景须有唯一有效原文范围；无法定位时要求补关联，不扩大成整章授权。
5. 生成结果进入候选区，逐项比较原文与候选后采纳或丢弃。采纳建立工作稿版本；正式事实仍须经过已有章节审查与提交流程。可从章节版本历史恢复采纳前正文。
6. 委托中断后保留已经生成的候选，恢复时仅执行剩余范围。结构、来源或依赖变化会暂停并要求重新授权。遇到供应商错误、窗口不足、引句无效时保留真实错误，不伪造结果。

## 视图与数据边界

| 能力 | 当前行为 |
|---|---|
| 故事地图 | 直接编辑现有场景／情节点及其关系；全书概览下钻到分卷／故事弧，再选择事件和场景。节点按面板实际宽度排列为每行 1–3 个，每页最多 48 个，避免把长篇全部铺开。并排视图在较窄窗口中用按钮展开导航与所选资料，保留正文阅读空间。 |
| 双时间线 | 叙述顺序来自章节与场景顺序；世界时间来自作者的数值坐标和明确先后关系。重排章节不改世界时间。没有可比较约束的事件保持不确定，层级展示不表示所有事件都有唯一全序。 |
| 正文反推结构 | 按章提取场景并诊断偏离。每个结果必须有实际存在的逐字引句；先保存建议，作者采纳后更新原场景或新建场景。批量计划及证据关联可一起撤销；不会直接写入正式事实库。 |
| 人物成长与关系 | 同一故事节点上的目标、信念、关系、处境与选择记录，可关联原文证据；显示已提交人物事实与伏笔状态。人物筛选复用同一组场景。 |
| 秘密与知情 | 分开记录事实、人物知情／误解及读者揭示节点；不以读者知情代替人物知情。诊断中的知情、动机和节奏判断属于带依据的 AI 编辑意见。 |
| 锁定 | 场景、人物／结局卡片和选区锁定覆盖工作台及原有 AI 写作入口；旧故事线编辑也遵守数据库锁定检查。作者仍可直接编辑正文，随后需要重新关联受影响的锁定证据。 |
| 剧情试验 | 从场景建立独立计划、因果结构、样稿和样稿事实。合并前检查计划、结构、正文和依赖冲突；合并后仍是待审工作稿。撤销合并同时恢复计划、结构和正文，保留撤销后的方案档案。当前试验以一个场景样稿为单位。 |
| 编辑诊断 | 动机、知情、伏笔、重复、节奏、情绪和计划偏离均链接原文；历史证据在正文已变化时显示历史引句，不伪装成当前选区。 |
| 文风偏好 | 作者选择样稿，AI 整理叙述／对白偏好，作者确认后进入生成上下文。禁用表达在候选采纳时检查；推导建议不会自动成为作者规则。 |
| 灵感与资料 | 分类保存研究资料、虚构设定和待选灵感，保留来源并关联故事对象。收件箱默认不随公开创作材料发布。 |
| 续作简报 | 最近编辑章节、未解决收件箱和未回收支线集中显示；创意讨论保存多个走向及人物／后续影响，均作为建议。 |

文学含义不能靠硬性范围检查保证。“必须发生”等语义约束会进入真实模型请求，候选仍需作者审阅；自动化测试不证明文学质量改善。

## 一致性、迁移与共享

- `packages/shared/src/storyGraph.ts` 定义统一结构、时间约束、原文关联、作者偏好和授权目标；桌面与服务端共享拓扑校验。地图、人物和时间线不维护独立大纲副本。
- 结构修改使用版本比较和原子事务；旧故事线更新保留仍存在的实体 ID，不再全删全建。跨作品关联、循环时间约束、缺失证据、并发覆盖均被拒绝。
- 正文证据建立前封存编辑会话；版本清理保留当前关联、未处理提取及可撤销结构所需的原文版本。
- 结构撤销按顺序执行；被其他入口改过的场景或合并后改过的正文会触发冲突，避免覆盖作者的新工作。普通正文编辑与候选采纳沿用章节版本历史。
- 创作材料沿用 V2 bundle 的显式分享入口，服务端通过 `storyGraphVersion: 1` 声明支持。图谱分成独立哈希块，保留现有 256 KiB 单块／16 MiB 总量限制；导入重映射实体、章节、版本和内部证据 ID，再校验原文与拓扑。
- 仅分享确认的关系、原文关联和偏好；委托、未采纳候选、剧情试验和收件箱留在本地。证据必须对应实际发布的已提交正文，过期关联阻止分享并给出原因。V1 正文分享保持原协议。

## 章节篇幅与独立审阅

章节数和字数是创作参考：初次规划用长、中、短篇规模估计，接受的故事弧决定实际目录长度；每章按剧情独立估计篇幅，不把章节预算缩放到固定全书总字数。小说不会因低于或超过某个字数比例自动补写、删减。模型输出上限仍是技术容量，不是小说章长要求。

每章完成后，由独立于正文写作的叙事审稿角色同时扫描场景完整性与冗余。`lengthReview` 返回保留、扩写、精简或两者兼有的结论；各建议引用本次审稿问题 ID，问题必须有当前正文唯一可定位的逐字证据与具体目的。缺失的选择、因果衔接、人物互动或兑现需要展开；重复说明、同功能场景与无效铺陈需要精简。不得只依据参考字数下判断。一般快慢、文风偏好显示给作者，不强制重写；明确结构缺陷在授权修订轮数内局部处理，保留锁定与无关原文，再次审查；跨出计划的改动等待作者。

旧报告未含篇幅扫描时显示“旧报告未扫描篇幅”，不补造已通过结论。显式重审或恢复对应审稿步骤会生成新报告。已暂停的整本书任务恢复时与已采纳的章节计划重新对齐：已撤下的空槽不再执行，新采纳章节加入队列；按指定章节委托的任务不扩大范围。撤下的空槽及原有任务步骤保留记录，已有正文和版本不会因此删除。

这些功能测试验证流程与证据约束，不证明文学质量提高；真实作者评阅仍需单独进行。
