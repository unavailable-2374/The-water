# 正文理解与第二批功能验收 · 2026-10-10

本轮验收使用独立原生 TEST 应用和数据库，不打开正式作品库。载入的小说均为 TEST 虚构作品；模型回答来自仓库保存的真实调用历史记录，导入时仅重绑定 TEST 副本中的 ID 和来源签名，不计作新的模型实验。大纲审查报告为逐字段标明 TEST / SIMULATED 的界面夹具；章节文风分 0 是明确标注的夹具占位，不是模型评分。

机器可读的源码摘要、TEST 库核对、操作范围与失败记录见 [验收证据](reader-acceptance-20261010.json)。

## 验收中修复的问题

1. 送入分支后原界面没有可见成功反馈。补充成功提示和明确的固定事实核对状态，原生复验已看到“已送入分支审阅，可在故事工作台的「剧情试验」中查看”。收益是作者能确认操作落点；提示仍不表示分支已经采纳。
2. 独立审查只核对样稿，继承的场景计划可能仍保留旧结论。分支现在保存本轮固定事实，并把作者确认绑定到计划与样稿内容 hash；改变任一项会取消确认。收益是防止未核对的旧计划随样稿合并；代价是多一次明确的计划核对，不能把这次作者确认当成自动模型审查。
3. WKWebView 中切换分区后，旧按钮和主导航的背景／文字颜色仍然残留。共享按钮不再过渡背景色，主导航立即切换选中颜色；保留按钮按压与阴影过渡。收益是选中分区与可见高亮一致，代价是失去颜色淡入效果。960 像素原生窗口实机复验，不以构建通过代替视觉结果。

## 自动验证与工具失败

分支修复后的针对性测试 15 项通过；桌面全量 1,099 项通过、12 项默认跳过。后续视觉修复的导航测试 9 项通过，原生打包同时执行 TypeScript 检查与 Vite 构建。验收后 TEST 库外键检查为空，各章工作稿与正式指针均未变化。共享与服务端沿用上一阶段通过的检查，本轮没有对应源码改动。

界面切换一次返回 `Computer Use server error -10005: frontmostApplicationChanged`，重新获取 TEST 应用后继续。窄窗口两次滚动工具调用返回 `Computer Use server error -10005: noWindowsAvailable`，未算通过；重新获取窗口后使用 Return / Tab 实际进入反馈区并观察到正文和反馈区。保留工具失败与真实观察的区别。

两份材料已经冻结，内容 hash 与私有版本映射保存在本机 TEST 验收数据中。现已收到用户的真实人工反馈，原话见 [人工反馈](reader-human-feedback-20261010.json)。原生操作记录和 JSON 保留当时快照，不回写历史结果；两份对应材料的意见已通过实际保存接口记入两个隔离 TEST 库，冻结文本不变。首次阅读目标可辨，但重要性、结尾推断缺少支持，读者没有被吸引。比较中 X 更愿意读，“道歉也可能带着下一步”有效；笔的收束突兀，两稿的道具与签字权因果均受到质疑。该读者没有读到合作等于原谅。**本轮文学效果未通过验收**；这是一位读者对两组短文本的反馈，不是总体模型准确率。总体文学质量、真实修订前后价值、长篇关系持续性仍需要后续真实作品评阅，不能由 UI 或程序通过项替代。
