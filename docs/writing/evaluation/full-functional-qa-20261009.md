## 实际修复

1. **提示词预览崩溃**：`src/llm/prompts/preview.ts` 中旧样例缺少必需 `logline`。补齐后 11 个已列出模板均可渲染，原生预览可打开；新增两项回归。优点是设置页可检查实际提示词；示例仍明确是括号占位样例，不是作品内容。
2. **回收站类型错误**：中英文文案把 TXT 等阅读文档统称 PDF；改为“阅读文档 / Reading document”。原生 TXT 回收站复核通过。优点是不会误报格式；文案仍不细分扩展名。
3. **真实剧情样稿引文校验太晚**：`src/novel/storyBranches.ts` 的事实引文原先在 JSON 请求返回后才验证，错误引文直接抛出 `Evidence quote is missing or ambiguous`。新增 `BranchSampleSchema`，在现有有限 JSON 修复流程内验证逐字引文；缺失或歧义引文要求模型重新生成，失败仍保留错误，不丢弃事实或伪造依据。三项新回归通过，真实工作台重跑通过。优点是可修复模型引文错误；额外修复请求可能增加耗时和费用，次数耗尽仍需作者处理。
4. **拆书排队与执行输入不一致、过滤后抽样漏章**：`src/novel/styleExtractionSources.ts` 统一输入资格检查，短文本导入不再自动创建必然失败的任务；手动提取在排队前说明输入要求。执行器按合格样本的位置抽样，并保留真实章节号作为来源。三项新回归及 32 项相关测试通过；原生两章短 TEST 导入后显示样本不足提示，数据库任务数为 0。优点是避免无效重试、避免漏掉后面的有效长章；保留原先已导入/已提交正文每章超过 200 字的提取条件，短正文不生成未经支持的文风结论。

认证重试的环境根因是 shell 中同名 `LUNAROUTE_API_KEY` 覆盖了 `apps/server/.env`。测试进程移除继承变量后，使用文件中的当前有效凭据通过；没有在聊天或记录中保存密钥。
