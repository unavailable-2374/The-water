# 长篇写作工作台：实现契约与验收

本页描述当前实现，取代旧文档中“待采纳版本即当前正式正文”“风格分数即提交门槛”“截断旧事实”的行为描述。小说按 300–500 章设计；非虚构保留章节生成入口，不建立论证树。

## 作者流程

1. 在创作资料中确认简报、全书主线与结局、分卷、人物动机和伏笔。分卷与故事弧独立；场景包含视角、时空、人物、目标、阻力、转折、结果、字数与事实依赖。
2. 新作品只细化最初五章。后续以最多五章滚动规划；AI 生成的是建议，显示前后内容与影响章节，作者采纳才生效。修改已确认资料会使受影响记忆与审查失效。
3. 自动流程为场景规划、逐场景草稿、章节衔接、叙事/文风审查、定点修订、事实提取、原子提交。场景缺少确认、前文记忆失效、必需上下文超限或阻断问题未解决时进入 `awaiting_review`。
4. 章节页提供章节/场景导航、CodeMirror 6 正文、助手和审稿。专注模式隐藏导航与助手。选区改写、光标续写、扩写、精简、对白与动作精修产生独立候选；逐项采纳进入工作稿，支持撤销。自动保存不会发布正式事实。讨论保存在 `novel_assist`；“应用到计划”先生成待采纳建议。
5. 前文重新提交后，后续正文保留，记忆和审查按最早变更位置失效；通过“重建记忆”依章复审、提取和提交。无法自动判断的资料依赖由作者核对。

优点是候选、正式正文与事实状态有明确边界；代价是规划确认、复审和重建增加调用，遇到实质矛盾会暂停。启动生成和助手调用前显示调用范围、token 和费用估算（不含网络/预算重试及 JSON 修复）；无价格匹配时金额未知，不能把账本中的占位零解释为免费。

## 版本与事务

- `chapters.current_version_id` 是工作稿；`committed_version_id` 是正式正文。`chapter_versions.content_hash` 为 SHA-256，已提交正文、hash 和摘要由 SQLite 触发器保护。
- 审查、提取、候选和提交绑定版本、正文 hash 与依赖 hash。过期审查不能用于新文本；历史审查的界面标签明确为历史结果。
- `Db.atomic(operations)` 由 Rust 在 Tauri SQL 插件的同一连接池执行 `BEGIN IMMEDIATE`。每条操作可指定 `expectedRows`；比较并交换失败时回滚。正式指针、提交记录、事实、派生快照与后文失效一起成功或回滚。
- 工作稿保存串行化；文本建议保护其基础版本不被清理。仅可验证的不重叠编辑允许重定位；原文或引用资料改变产生冲突，候选保留。尚未保存的文本写入恢复日志，下次打开须明确恢复或丢弃。
- 拆分与排序保留稳定章节 ID 和结构记录。合并先产生候选，通过审查提交后才归档第二章；未提交前可取消。归档正文可在资料页查看。
- 导出、发布默认读取正式正文，草稿导出需明确选择。候选丢弃不修改正式记忆。

## 记忆与审校

`writing_cards` 存计划，`canon_events` 存正文已经发生的事实、事件、关系、状态、人物知识及伏笔进度。每项事件具有稳定记录 ID、正文版本/hash、UTF-16 原文范围、逐字证据及依赖 ID。人物知识通过 `knownBy` 与事件证据表达；计划不能进入既成事实。

完整事件历史不截断。派生故事记忆快照记录提交 ID 集合，按不可变事件重建，避免每章复制此前全部事实。上下文按人物、场景、时空、伏笔及依赖递归检索；近期正文只读取前两章。必需规则、当前场景和依赖证据无法放入模型窗口时暂停。事实列表每页 50 项，已选但不在当前页的依赖保留可见。

基础叙事审查不要求文风档案，覆盖因果、动机、声音、知识边界、时空、设定、伏笔与结局。阻断必须具备原文、依据与建议；来源 ID 必须来自实际提供的上下文。样式评分仅供参考。新配置默认最多自动修订两轮；原有显式配置保留。轮数与修订版本在同一事务中保存，恢复同一任务不能重置上限。每次审稿先保存证据，再尝试修订；修订请求失败仍可查看问题。

修订只接受逐字定位、不重叠、实质覆盖问题证据的局部补丁。同一问题涉及相邻对白时合并为连续补丁，中间无关原文必须保留。正文被输出上限截断时，最多两次在配置上限与上下文预算内扩大预算重试，累计所有已报告用量；仍截断则明确失败，不保存截断稿。仍有阻断则等待作者编辑、重审，或填写误报依据；决定留痕。必需审查、提取和提交不能用跳过失败绕过。

来源可定位不等于语义一定正确，人工仍需判断误报、遗漏与文学质量。重新提取形成新的事件记录；系统不会凭文本相似度把旧事实 ID 自动认定为新事实。失效的场景依赖需重新关联。

## 旧库、备份与恢复

桌面迁移 `0009_writing_workbench.sql` 保留历史版本和计划；旧正式正文标为 `legacy`，既有待采纳稿保持候选身份，不生成虚假的审查通过记录。旧任务升级为必需门禁流程，中断的运行步骤恢复为待运行并保留已有输出。继续自动写作前必须按顺序重建缺失或失效记忆。

备份使用 SQLite `VACUUM INTO` 获取含 WAL 的一致快照。恢复校验文件头、版本、数据库完整性、外键和关键表，暂停并排空任务，创建保险备份，再由 Rust 关闭现有连接池并安装暂存文件；恢复后重启。文件缺失等错误不能被解释为成功。

## 共享协议

- V1 请求与 Bundle V1 保持兼容。新客户端读取 V1/V2；服务端能力接口声明创作资料支持。
- “共享已确认创作资料”默认关闭。选择共享但旧服务端不支持时明确报错。
- `CreationMaterials` 清单版本 1 搭配 Bundle V2；一卡一块，canonical JSON + SHA-256 校验，每块最多 256 KiB、每作品最多 16 MiB。上传和版本提交均核验完整性、证据、引用及依赖顺序。
- 只共享已确认规划及正式事实。候选、私人讨论、审稿记录、任务日志不在共享 schema 中。下载继承作品可见性与二创授权检查。
- 二创导入重映射本地 ID，保留来源版本、原始卡片和证据。来源资料可单独查看；导入证据不伪装成本地审查通过。场景依赖须核对并重建本地正式记忆后确认。
- 服务端需应用 `0005_curly_lady_ursula.sql`；客户端桌面库与服务端库是独立迁移体系。本次没有部署服务端或发布任何作品。

## 验证与边界

回归测试覆盖候选隔离、版本不可变、hash/依赖过期、事务中断回滚、重复提交、任务恢复、前文失效、章节合并、局部建议冲突、V1/V2 导入、权限、缺块与 hash 错误。新增测试夹具均标识 TEST，不作为写作质量证据。

`test/writing/scale.test.ts` 建立 500 章、至少百万中文字、2,500 条带证据事实的 TEST 工程，核验有界上下文、前两章正文读取、早期必需事实保留及历史快照可重建。`test/writing/scenes.test.ts` 核验多场景中断恢复与规划整批回滚。

真实调用、人工盲评及原生界面验收记录见 [evaluation/README.md](evaluation/README.md)。自动断言通过不证明小说质量提升，中文粘贴不等于输入法组合事件验收。

## 推理控制与读者理解

迁移 `0010_reasoning_effort.sql` 单独保存 OpenAI-compatible 服务声明支持的 low/medium/high；空值保留服务端默认，不按模型名称猜测支持。推理预留只增加容量，不能控制推理强度。备份版本升为 10，Rust 从注册迁移读取最高版本，避免备份校验与迁移漂移。

小说正文提示要求自然交代已确认背景和选择代价，关键行为呈现触发与权衡，保留秘密揭示顺序；普通共情不足为建议，确切冲突仍阻止提交。非法或缺失审查 verdict 不能默认通过。优点是读者无需先读设定卡才能理解行为；代价是更多上下文与不确定的额外修订，质量必须靠真实稿件和人工评阅判断。

开发者后端模型任务已接入 [Pi harness](server-harness.md)，供应商密钥仅由后端配置。默认客户端使用自己的云端登录凭证，模型请求具有持久队列、幂等与回放；章节领域流水线仍由桌面编排，退出桌面后不会自动启动后续章节步骤。桌面持有正式正文与作者采纳权；后端结果不能绕过版本/hash/依赖门禁。用户无总预算上限不等于模型没有单次容量限制，也不等于允许无证据地通过审校。

叙事模型的输出契约现在只包含 `evidence.quote`，不生成位置占位值；`locateNarrativeIssues` 在当前版本上唯一匹配后生成真实 `from/to`。缺失或重复引文明确失败。新模型依据与建议各最多 800 字、来源最多 20 项；超限要求重新生成，不静默截短。存储用的 `ReviewIssueSchema` 保持兼容旧报告，UI 仍接收完整、已校验的 UTF-16 位置。相关新测试覆盖中文、emoji、歧义与旧报告兼容，旧作品不因生成接口变更丢失审稿。

## 人物、情节与阅读回应

新小说大纲先说明主要体验、独特方式与限制、首篇选择与后果、故事发动机制和结束条件；主要人物目标卡补充恐惧、信念、应对习惯和独立事务。旧卡缺少这些字段时保持缺省，不编造补齐。新生成场景必须给出 readerInterest、choice、choiceReason、consequence、beforeState、afterState 与 presentation（展开/概述）。静态计划不是已发生事实。

小说短稿不再自动扩写；作者主动扩写仍可使用，非虚构保留字数处理。重要选择和互动展开，过渡及重复操作概述，不强迫每章反转。

审阅结果新增“故事推进（AI编辑判断）”：本章关注、前后变化、期待推进/兑现/延后、下一阅读关切和修订理由，证据必须逐字且唯一定位当前正文。无硬冲突不等于小说质量合格；文风分数不是读者评分。具体动机、因果、信息、伏笔、结尾、重复问题可触发有轮数上限的局部修订；个人文风偏好不触发。需要改变确认计划时等待作者调整，不自动改结局或事实。已提交正文的自动修订形成待采纳候选。

后续章节只使用有效已提交版本及其对应审查中的故事推进与期待记录，不使用未采纳候选、未来计划或失效记忆，也不声称这是实际读者反馈。旧报告明确标示未评估故事推进。
